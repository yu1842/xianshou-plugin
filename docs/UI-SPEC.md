# UI 设计规范 · 先手协议卡片

> 本规范适用于插件在会话内产出的所有卡片。
> 设计令牌的唯一真源是 `src/ui/tokens.ts`，导出物是 `docs/ui-tokens.css`（由 `npm run tokens` 生成，禁止手改）。
> 真实渲染样例见 `docs/SAMPLE-OUTPUT.md`（由 `npm run sample` 跑出来的，不是画的）。

---

## 1. 设计定位

这套卡片继承《先手协议》方案文档的版式语言：**纸色底、墨色正文、赭石强调、青灰辅助**。
目的不是"好看"，而是让用户在对话框里看到的东西，和他在方案里读到的规则是同一套 —— 认知一致本身就是降低摩擦。

三条硬约束：

1. **卡片是说服的终点，不是说教的起点。** 每张卡最多一个"下一步"，且必须是可执行动作。
2. **数字必须带含义。** 只给比例不给解释，用户会把它当 KPI；给了含义，它才是"可见的债"。
3. **颜色不可依赖。** 终端、色弱、纯文本导出都可能丢色，所以每种语义必须同时有符号。

## 2. 设计令牌

| `accent` | `#b45309` | `#e0a061` | 赭石：需要你决定的事 |

### 2.2 语义色（tone）

组件只说 tone，不说颜色。tone → 颜色 + 符号的映射在 `toneStyle()` 里，任何地方不得绕过它直接写 hex。

| tone | 语义 | 符号 | 使用场景 |
| --- | --- | --- | --- |
| `neutral` | 普通信息 | `·` | 状态查询、无风险提示 |
| `accent` | 需要你决定 / 注意 | `◆` | 黄区、需回收、建议动作 |
| `teal` | 流程推进 / 已完成一步 | `◇` | 落稿放行、交付、回收提醒 |
| `danger` | 被拦 / 被打回 / 越界 | `▲` | 闸门拦截、比例超 60%、回收失败 |
| `success` | 健康 / 通过 | `✓` | 比例正常、回收通过、拒绝率健康 |

> 符号是必需项，不是装饰。`test/ui.test.js` 会断言五种 tone 的符号与前景色互不重复。

### 2.3 字体与字号

| 令牌 | 值 | 说明 |
| --- | --- | --- |
| `reading` | Source Han Serif SC / Songti SC / Noto Serif CJK SC / Georgia | 正文衬线，与方案文档一致 |
| `label` | ui-sans-serif / -apple-system / Segoe UI / Microsoft YaHei | 标签、徽标、脚注 |
| `mono` | ui-monospace / SFMono / Menlo / Consolas | 任务 ID、判据 ID、命令 |
| 字号 | display 22 / title 17 / body 15 / label 12 / caption 11 | 卡片标题用 title，正文 body |
| 行高 | reading 1.75 / compact 1.45 | 中文正文必须 ≥1.7，否则密不透气 |
| 字距 | label `0.12em`、body `0.01em` | 仅标签加宽字距 |

在纯文本卡片里，字体不可控，因此**层级只能靠符号、缩进、空行表达**，不能靠字号。

### 2.4 间距与边框

| 令牌 | 值 |
| --- | --- |
| `spacing` | xxs 2 / xs 4 / sm 8 / md 12 / lg 18 / xl 26 |
| `radius` | none 0 / sm 2 / md 4 / pill 999 |
| `border` | hair 1 / rule 2 / accent 4 |

卡片圆角一律 `sm(2px)`：方案文档是纸感版式，大圆角会变成"App 通知"，语气就错了。

## 3. 组件规范

### 3.1 卡片（CardModel）

```
{符号} {标题}
  {副标题}
（空行）
节点…
```

- 标题：一句话说清"发生了什么"，不超过 24 个汉字。
- 副标题：可选，补充对象（任务名 / 窗口名），一句话。
- 节点顺序固定：**结论 → 依据 → 数字 → 建议动作 → 脚注**。
- 单卡节点数 ≤ 10；超过就说明这张卡装了两件事，应拆。

### 3.2 节点类型

| kind | 渲染 | 规则 |
| --- | --- | --- |
| `heading` | `▸ 文本` + 空行 | 一节最多一个，用于切"为什么 / 下一步 / 判定" |
| `paragraph` | 原样 | 一句一段，不超过 3 行 |
| `badge` | `[文本]` | 分区、状态标签，不超过 8 字 |
| `kv` | `  标签　值` | 全角空格分隔，标签 ≤ 6 字；用于可枚举的事实 |
| `meter` | `  标签　▓▓▓▓░░░░ 62%　说明` | **固定 12 格**，比例四舍五入；必须带 caption 说明口径 |
| `list` | `  · 项` / `  1. 项` | 有序用于步骤，无序用于并列；最多 5 项 |
| `callout` | `符号 标题　正文` | 一张卡最多一个；用于"唯一的硬要求"这类关键提醒 |
| `divider` | `────` | 固定 4 个 `─`，用于结论与依据之间 |
| `footnote` | 小字 | 任务 ID、阈值口径、错误码 |

计量条的 12 格是硬规范：格数随宽度变化会让"62%"看起来像"70%"，这类视觉误差在阈值敏感的场景里等同于错误信息。

### 3.3 六类业务卡片

| 卡片 | 类 | tone 规则 | 必须包含 |
| --- | --- | --- | --- |
| 分区卡 | `ZoneCard` | 红= danger / 黄= accent / 绿= success | 判据 ID、下一步 |
| 闸门卡 | `GateCard` | danger | 为什么被拦、怎么过闸、20 分钟产不出东西时该做什么 |
| 留痕卡 | `LedgerCard` | 按 band | 三段权重、比例、判定、建议动作 |
| 回收卡 | `RecallCard` | 到期 teal / 逾期 danger | 三个具体问题、判定标准、提交方式 |
| 拒绝率卡 | `RefusalCard` | 盲从 danger / 健康 success | 健康区间、样本数、推导（仅在盲从时） |
| 健康度卡 | `HealthCard` | 有危险项 accent / 否则 teal | 四指标、样本量、口径说明 |

## 4. 交互规则

1. **一卡一动作。** 每张卡只有一个"下一步"。两个动作等于没有动作。
2. **动作必须在当前工具集内可执行。** 写"去反思一下"是废话；写"调用 `xianshou_draft`"才是动作。
3. **拦截必须给出逃逸路径。** 闸门卡永远包含"怎么过闸"三步，否则用户的第一反应是关插件。
4. **不改状态的操作不发卡。** 纯查询才允许"信息卡"（如 `status` 列表）。
5. **失败也是一张卡。** 静默失败会让用户以为操作成功；失败卡必须带错误码与修正动作。
6. **不做二次确认。** 确认类交互交给宿主的审批机制（闸门 `ask` 模式），插件不自己发明弹窗。

### 4.1 状态矩阵

| 状态 | 表现 | 例子 |
| --- | --- | --- |
| 空态 | neutral + 一句"下一步做什么" | 无任务列表：`还没有任何任务` |
| 样本不足 | neutral，显式写"样本不足"，**不显示 0%** | 健康度四指标全空 |
| 降级 | 脚注说明缺了什么能力 | 无 `pre-execute` 时闸门不出卡 |
| 逾期 | danger + 逾期小时数 | 回收窗口超过宽限期 |
| 错误 | danger + 错误码 + 修正动作 | `DRAFT_TOO_THIN` |

## 5. 文案规范

### 5.1 必须

- 用第二人称"你"，不用"用户"。
- 数字后紧跟含义：`[AI] 占比 62% —— 你交了一份自己没参与建造的东西`。
- 拒绝时给理由，不给态度：`低于 80 分钟` → 说明"若 20 分钟产不出东西，说明该补背景"。
- 保留方案原文的关键句，因为它已经过打磨：如"说不出来，就是没学会"。

### 5.2 禁止

| 禁止 | 原因 | 替代 |
| --- | --- | --- |
| `请注意` / `建议您` | 空指令，无可执行内容 | 直接写动作与代价 |
| `加油` / `努力` / `一定要` | 说教语气，会触发反感 | 用数字和机制说话 |
| emoji | 与纸感版式冲突，且终端渲染不一致 | 使用 §2.2 的几何符号 |
| 纯颜色表达状态 | 色弱/终端不可读 | 符号 + 文字 |
| 无数据的百分比 | 编造指标比没有指标更糟 | `样本不足` |
| 一张卡放两个"下一步" | 决策瘫痪 | 拆卡 |

> `test/ui.test.js` 会用正则断言卡片文本不含 `请注意|加油|努力|一定要`，且不含伪造的 `0%`。

## 6. 主题适配

| 模式 | 行为 |
| --- | --- |
| `ui.theme = "light"` | 强制浅色 |
| `ui.theme = "dark"` | 强制深色 |
| `ui.theme = "auto"`（默认） | 跟随宿主；宿主不可知时回落浅色 |

回落浅色而不是深色，是因为用户第一次打开时应该看到和方案文档一致的纸色，而不是一个突然变黑的界面。

深色不是简单反色：`accent/teal/danger/success` 在深色底上都提高了明度（`#b45309 → #e0a061`），否则在 `#14181d` 上对比度不足。

## 7. 可访问性

1. **对比度**：正文 `ink` 对 `paper` 在浅色下为 14.8:1，深色下为 12.6:1，均高于 WCAG AA 的 4.5:1。
2. **不依赖颜色**：每种 tone 有独立符号（§2.2），色盲与纯文本环境仍可区分。
3. **不用字号做唯一层级**：层级靠符号、缩进、空行，因为终端字号不可控。
4. **动效为零**：卡片不引入动画，避免阅读顺序被打断，也便于会话回放。
5. **可复制**：所有关键信息（任务 ID、判据 ID、命令）放在 `kv` 或 `footnote` 中，便于直接复制。

## 8. 实现约束（给改 UI 的人）

1. **视图不拼字符串**：`views/*` 只产出 `CardModel`，所有排版在 `MarkdownCardRenderer`。想在标题加个符号，改 renderer，不要在视图里写 `"▸ "`。
2. **视图不判断阈值**：阈值判断在 `LedgerPolicy` / `RefusalPanel` / `HealthReportBuilder`。视图拿到的已经是结论。
3. **渲染必须确定性**：`render(model)` 对同一输入必须产出完全相同文本（无时间戳、无随机数）。时间必须在视图构造时传入。
4. **令牌只改一处**：改颜色改 `tokens.ts`，然后 `npm run tokens` 重生成 CSS；跑 `test/ui.test.js` 确认没有漂移。
5. **新增节点类型**：先在 `CardNode` 加变体，再在 `MarkdownCardRenderer.#node()` 与 `PlainCardRenderer` 各加一个分支，最后补一条渲染测试。三条缺一不可 —— 否则 `Plain` 渲染器会静默丢内容。
